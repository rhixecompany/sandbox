# Hermes Root Scripts Quick-Command Coverage

## Goal
Make every first-party executable script directly under `C:/Users/Alexa/AppData/Local/hermes/scripts` discoverable through Hermes `quick_commands`, without executing potentially destructive script logic during smoke tests.

## Scope
**Included:** `.py`, `.sh`, `.bash`, `.ps1`, `.ts`, and `.js` files in the scripts root.
**Excluded:** nested directories (including `node_modules`), generated bytecode, backups/snapshots, and unrelated project scripts.

## Requirements

### FR-001: Deterministic script inventory
**Priority:** P0 (Critical)
**Acceptance criteria:**
- [ ] Inventory is sorted by filename and uses normalized relative names
- [ ] Vendored and nested files are excluded (node_modules, __pycache__, caches, snapshots)
- [ ] Missing or duplicate script names fail validation
- [ ] Script count is deterministic and repeatable

### FR-002: Safe quick-command registry
**Priority:** P0 (Critical)
**Acceptance criteria:**
- [ ] Every inventoried script has one unique quick-command key
- [ ] Existing user commands (`diff`, `gc`, `log`, `pr`, `st`, `tree`, `ws`) remain present
- [ ] Generated entries use Hermes-supported `{type: exec, command: <string>}` objects
- [ ] Generated commands invoke the auditor wrapper in non-destructive `audit` mode; they do not run the target script
- [ ] Commands include `--scripts-dir` parameter for cross-directory support

### FR-003: Config synchronization
**Priority:** P0 (Critical)
**Acceptance criteria:**
- [ ] The canonical quick-command block is written through `hermes config set --force quick_commands ...`
- [ ] All active Hermes profile `config.yaml` files contain an equivalent quick-command block
- [ ] Profile-specific model, provider, plugin, and platform settings are unchanged
- [ ] Snapshot and backup config files are excluded from synchronization
- [ ] Sync verification passes with 0 diffs on managed keys

### FR-004: Command smoke tests
**Priority:** P0 (Critical)
**Acceptance criteria:**
- [ ] Each generated command is parsed without secrets
- [ ] Each wrapper invocation exits zero in audit mode
- [ ] The final registry count equals the discovered script count plus preserved user commands
- [ ] A malformed or missing command fails with a non-zero exit code and actionable diagnostic
- [ ] Smoke test completes in < 60 seconds for 265 scripts

### FR-005: Environment safety
**Priority:** P0 (Critical)
**Acceptance criteria:**
- [ ] All `.env*` files under the repo and Hermes home are inventoried by path
- [ ] Only variable names and file classes are compared; values are never printed, copied, or synchronized
- [ ] Project `.env` files and Hermes profile credentials are reported as separate scopes
- [ ] 20 SandBox .env files and 57 Hermes .env files inventoried

### FR-006: Scripts-judge integration
**Priority:** P1 (High)
**Acceptance criteria:**
- [ ] The scripts-judge workflow requires quick-command coverage for Hermes root scripts
- [ ] The judge exposes a checkable registry/config input and reports missing, stale, and malformed entries
- [ ] Existing syntax, CLI, error-handling, documentation, and DRY checks remain intact
- [ ] Judge scores ≥ 98 with threshold 98

### FR-007: Windows execution
**Priority:** P1 (High)
**Acceptance criteria:**
- [ ] Paths use native Windows-compatible invocation from Hermes quick commands
- [ ] The wrapper supports `--help`, JSON output, and deterministic exit codes
- [ ] Validation does not require PowerShell elevation, network access, or credentials

## Non-Functional Requirements

### NFR1: Performance
- Quick command generation: < 30 seconds
- Smoke test for 265 scripts: < 60 seconds
- Environment sync: < 10 seconds
- Config sync across 14 profiles: < 5 seconds

### NFR2: Reliability
- All operations must be idempotent
- Rollback must be possible for all changes via git
- No data loss during sync or cleanup

### NFR3: Security
- No secrets in output or config.yaml
- .env files must not be committed
- Credential pool strategies must be maintained

### NFR4: Maintainability
- All scripts must have quick_commands
- All skills must follow SKILL.md format
- All plans must follow .hermes/plans/ format
- Documentation must be updated with changes
