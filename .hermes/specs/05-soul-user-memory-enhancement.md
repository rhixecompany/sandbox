## Goal

Enhance SOUL.md, USER.md, and MEMORY.md with Git history insights, session continuity, DRY compliance, and profile routing table enforcement. Ensure all three files are properly structured with no H1 headings and use §-delimited format for machine parsing.

## Requirements

### SOUL.md Enhancements
- [ ] Authoritative persona (OWL: pragmatic senior engineer)
- [ ] Cognitive style (deconstruct before acting, trace before fix, one variable at a time, surface assumptions, resourceful not interrogative)
- [ ] Execution frameworks (Plans, Prompts, Skills, Hooks with specific rules)
- [ ] Architectural invariants (Plan Discipline, Prompt Construction, Skill Execution, Hook Lifecycle)
- [ ] Standing rules (13 rules, numbered)
- [ ] Memory hierarchy table
- [ ] 4 Mandatory Rules table (Session Start, MCP First, Profile Selection, Python Scripts)
- [ ] NO H1 heading (MD041 false positive)
- [ ] §-delimited format for machine parsing

### USER.md Enhancements
- [ ] Compact pointer (not duplicate of SOUL.md/MEMORY.md)
- [ ] Identity, Environment Stack, Model, Execution Preferences
- [ ] Standing Goal (prompt library maintenance)
- [ ] Honcho Memory status
- [ ] Cross-references to SOUL.md and MEMORY.md (DRY)
- [ ] Profile routing table
- [ ] NO H1 heading

### MEMORY.md Enhancements
- [ ] §-delimited facts (no H1, MD041 false positive documented)
- [ ] Git history insights: `git log --oneline` key commits summarized
- [ ] Session-derived updates section (practice→skill)
- [ ] Environment facts (paths, versions, tooling quirks)
- [ ] Lessons learned (corruption patterns, bulk-edit pitfalls, Windows quirks)
- [ ] Cross-profile facts (model, provider, repo, MCP servers)
- [ ] Current session context (active session ID, profile, model)
- [ ] NO H1 heading

### Session Continuity
- [ ] SESSION_REPORT.md rolling summary (real content, not stub)
- [ ] At minimum: session ID, timestamp, profile, model, work completed, tools/skills, current state, result
- [ ] Generated by session-logger v1.5.0 on session_end
- [ ] Read at session start per Rule 1

## Acceptance Criteria

| Check | Command | Expected |

| SOUL.md valid | `validate-memories` | Pass |

## Non-Functional Requirements

DRY compliance: no duplicate content across SOUL.md, USER.md, MEMORY.md. No H1 headings in any of the three files (MD041 false positive documented). MEMORY.md uses §-delimited format. SESSION_REPORT.md must contain real content (not a stub). Git history insights must be integrated from recent commits. Validation tool (validate-memories) must be available and pass all three files.
