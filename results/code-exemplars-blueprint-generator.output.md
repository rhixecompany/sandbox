## 2. Exemplars by Pattern Type

### Category A — Abstract Base Class / Template Method (`Pattern Type`)

Establishes a consistent contract and shared error handling across all data access objects.

**Example A1 — `src/dal/base-dal.ts` (BaseDal)**
The contract every DAL inherits. Defines `list`, `getById`, `create`, `update`, and an
optional `delete`, plus a protected `handleError` that maps DB constraint messages to
friendly errors (UNIQUE → "already exists", FOREIGN KEY → "related record not found").

```ts
export abstract class BaseDal<T> {
  abstract list(options?: DalOptions): Promise<T[]>;
  abstract getById(id: number | string): Promise<null | T>;
  abstract create(data: unknown): Promise<T>;
  abstract update(id: number | string, data: unknown): Promise<null | T>;
  abstract delete?(id: number | string): Promise<void>;

  protected handleError(error: unknown, operation: string): never {
    console.error(`[${this.constructor.name}] ${operation} failed:`, error);
    if (error instanceof Error) {
      if (error.message.includes("UNIQUE")) throw new Error("This record already exists");
      if (error.message.includes("FOREIGN KEY")) throw new Error("Related record not found");
      if (error.message.includes("NOT NULL")) throw new Error("Required field is missing");
    }
    throw new Error(`Failed to ${operation.toLowerCase()}`);
  }
}
```

*Comment: Use this as the reference for any new DAL — inherit `BaseDal<T>`, implement the
four required methods, and rely on `handleError` for constraint mapping rather than
re-implementing try/catch per class.*

### Category B — Repository / Singleton Data Access Object (`Pattern Type`)

Concrete DAL extending the base, with type-inferred rows from Drizzle schema and a module-level singleton.

**Example B1 — `src/dal/user-dal.ts` (UserDal)**
Best-in-class example: infers row type via `typeof user.$inferSelect`, exposes the canonical
CRUD plus domain queries (`getByEmail`, `search`, `updateRole`), stamps `updatedAt` on writes,
and exports `export const userDal = new UserDal();`.

```ts
import { desc, eq, ilike } from "drizzle-orm";
import { db } from "@/database/db";
import { user } from "@/database/schema";
import { BaseDal, type DalOptions } from "./base-dal";

type UserType = typeof user.$inferSelect;

export class UserDal extends BaseDal<UserType> {
  async getById(id: string): Promise<null | UserType> {
    const result = await db.select().from(user).where(eq(user.id, id)).limit(1);
    return result[0] ?? null;
  }
  async create(data: Omit<UserType, "createdAt" | "id" | "updatedAt">) {
    const [result] = await db.insert(user).values(data).returning();
    return result;
  }
  async update(id: string, data: Partial<Omit<UserType, "id">>) {
    const [result] = await db.update(user).set({ ...data, updatedAt: new Date() })
      .where(eq(user.id, id)).returning();
    return result ?? null;
  }
}
export const userDal = new UserDal();
```

*Comment: This is the canonical DAL shape. New entities should mirror `UserDal`: infer the
row type, keep `getById` returning `null` on miss (not throw), and always set `updatedAt`.*

### Category C — Strategy Pattern with Runtime Dispatch (`Pattern Type`)

Storage layer dispatches image handling across three interchangeable modes behind one interface.

**Example C1 — `src/storages/image-strategy.ts` (ImageStrategy)**
The dispatcher. `processImage` switches on `this.mode`; `batchProcess` adds bounded concurrency
(default 5) with a promise queue and per-item error fallback. `createImageStrategy` is the factory.

```ts
export class ImageStrategy {
  private mode: "imagekit" | "local" | "urls";
  async processImage(url: string, entityType: string, entityId: number | string): Promise<ImageResult> {
    if (!url) return { success: false, error: "Empty URL" };
    switch (this.mode) {
      case "local":   return await imageDownloader.download(url, entityType, entityId);
      case "imagekit":return await imageKitUploader.upload(url, entityType, entityId);
      case "urls":
      default:        return { success: true, url };
    }
  }
  async batchProcess(urls: string[], entityType: string, entityId: number | string, concurrency = 5) { /* bounded queue */ }
}
export function createImageStrategy(context: ImageStrategyContext): ImageStrategy {
  return new ImageStrategy(context);
}
```

*Comment: Add a new storage backend by implementing the same `Promise<ImageResult>` contract and
adding a `case` here — no caller changes required.*

### Category D — Resilient I/O with Validation, Retry & Caching (`Pattern Type`)

A concrete strategy implementation demonstrating production-grade download hardening.

**Example D1 — `src/storages/image-downloader.ts` (ImageDownloader)**
Exemplar for safe external I/O: `isSafeUrl` blocks localhost/private IPs (SSRF guard),
`validateBeforeDownload` does a `HEAD` pre-check (content-type + 10 MB cap), download uses
`AbortController` timeouts + exponential-backoff retry (3 attempts × `baseDelay * 2^attempt`),
and caching is layered (in-memory `urlCache`, filesystem `skipIfExists`, URL→path map).
De-duplication by hash runs post-download before final rename.

```ts
private isSafeUrl(urlString: string): boolean {
  const url = new URL(urlString);
  if (!/^https?:$/.test(url.protocol)) return false;
  const h = url.hostname.toLowerCase();
  if (h === "localhost" || /^10\./.test(h) || /^192\.168\./.test(h) /* ... */) return false;
  return true;
}
// retry loop:
for (let attempt = 0; attempt < maxRetries; attempt++) {
  try { /* fetch + pipeline to write stream */ break; }
  catch (error) { /* exponential backoff */ await this.sleep(this.baseDelay * Math.pow(2, attempt)); }
}
```

*Comment: Reuse `isSafeUrl` + `AbortController` + backoff template for ANY outbound fetch in the
codebase. Do not hand-roll `fetch` without the SSRF guard.*
